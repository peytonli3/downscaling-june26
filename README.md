# 26.6_wind

Wind downscaling: an EnsCGP (ensemble-conditional Gaussian process) posterior
first-guess, refined by a Swin2SR transformer that predicts per-pixel quantiles
(q10/q50/q90) of ERA5-to-WRF downscaled wind (u, v), supervised with a
Laplacian-pyramid / sliced-Wasserstein multiscale loss.

![Predicted quantile fields against WRF truth](docs/figures/swin_quantile_panels.png)

*ERA5 input and the EnsCGP first guess (left), WRF truth, and the model's
q10/q50/q90 wind-speed fields. Generated by
`extra_scripts/swin/eval_checkpoint.py`.*

## Results

Held-out test split (1010 samples in 100 storm events), `runs/0714` — the
**v6-0714** architecture, which remains the best model on this split (see the
head-to-head note below). Units are m/s, cells are `u / v`. "top 5%" is the
windiest 5% of *each sample's* pixels by wind speed, so every predictor is scored
on identical pixels drawn from the WRF truth.

| | MAE all | RMSE all | MAE top 5% | RMSE top 5% |
|---|---|---|---|---|
| ERA5 bicubic | 1.847 / 1.904 | 2.868 / 2.961 | 3.569 / 3.696 | 5.131 / 5.684 |
| EnsCGP posterior mean | 1.804 / 1.863 | 2.697 / 2.786 | 3.762 / 4.088 | 5.056 / 5.586 |
| EnsCGP/bicubic blend (α=0.5) | **1.678 / 1.732** | **2.602 / 2.677** | 3.539 / 3.751 | 4.909 / 5.388 |
| **This model (q50)** | 1.678 / 1.746** | 2.611 / 2.792 | **3.262 / 3.540** | **4.586 / 5.367** |

Every number above is aggregated at the **event** level — the metric is reduced
within a storm first, then averaged unweighted over storms — because samples
inside an event are consecutive hours and are not independent draws. All four
rows come from one pass of `extra_scripts/swin/eval_results_table.py`
(`runs/0714/figures/results_table_test.csv`, which also carries the top-10%
stratum); its model row reproduces the `v6-0714` column of the independent
`eval_model_scorecard.py` bit-for-bit.

**The ordering reverses between the bulk and the tail.** On all pixels the tuned
EnsCGP/bicubic blend is ahead — though only barely on MAE u, where the two are
level to within 0.0004 m/s. In the top 5% the model wins **all four** cells, and
by a far larger margin than it concedes in the bulk: 0.28 m/s on MAE u against
the blend, 0.32 on RMSE u. The same flip holds at top 10%, with the one exception
of RMSE v, where the blend edges back ahead by 0.03.

This is the intended trade, not a surprise: q50 is deliberately *not* trained on
a pointwise error — it is supervised only by the displacement-tolerant structural
losses, because pointwise objectives are minimised by blurring, and a blurred
wind field is the wrong answer even when its MAE is good. The blend buys its bulk
MAE by being smooth, and pays for it exactly where the wind is strongest. Note
also that the EnsCGP posterior mean, which beats bicubic in the bulk, is the
*worst* of the four in the tail.

**And the baselines have no uncertainty at all.** The model additionally emits
q10 and q90, so it is the only row that can be scored probabilistically — its
3-quantile CRPS is 1.115 / 1.158, with no baseline number to compare against.
That is why CRPS is not a column above: a column with one populated cell invites
a comparison that cannot be made. The envelope is instead assessed on its own
terms, by calibration:

| Nominal | Empirical coverage (u) | Empirical coverage (v) |
|---|---|---|
| q10 → 0.10 | 0.103 | 0.106 |
| q50 → 0.50 | 0.491 | 0.511 |
| q90 → 0.90 | 0.899 | 0.898 |

Coverage sits within ~1.1 points of nominal at all three levels, and monotonicity
(q10 ≤ q50 ≤ q90) holds by construction rather than by penalty. Restricted to the
same top-5% stratum as the table, q90 coverage falls to 0.836 / 0.809 — the
envelope is over-confident exactly where the problem is hardest. That is the open
item, not a solved one.

![PIT histogram](docs/figures/quantile_pit_histogram.png)

*Probability-integral-transform histogram: bin fractions against the nominal
[.10 .40 .40 .10]. Generated by `extra_scripts/swin/eval_quantile_calibration.py`.*

**Why v6-0714 and not the newer architecture.** The v7 line (`0729_meangate`,
which restored `mean_gate`) was the later attempt, and it did not improve on
v6-0714. The full head-to-head with paired bootstrap CIs is in
`runs/0729_meangate/figures/scorecard/scorecard_test.csv`
(`extra_scripts/swin/oneoff/eval_model_scorecard.py`): v6-0714 is ahead on the
all-pixel metrics (14 of 16 scored comparisons), and in both wind strata the two
are mostly indistinguishable — 11 of 16 comparisons have a 95% CI on the
difference that spans zero, with the rest split roughly evenly. So v7 costs bulk
accuracy and buys nothing measurable in the tail, which is why the results above
are v6-0714.

## Layout

```
scripts/              The live pipeline. Flat by design -- modules import each other
                      by bare name. paths.py resolves every path in the repo.
extra_scripts/
  data_prep/          Builds data/ from the upstream wndata.mat + DEM.
  enscgp/             EnsCGP stage: sigma tuning, neighbor diagnostics,
                      variance recalibration.  graphing/ for its plots.
  swin/               Swin stage. The recurring evals live at this level;
                      _common.py is the shared harness they all use.
    graphing/         Plots (training curves, band decompositions).
    oneoff/           One-time investigations, kept for provenance rather than
                      rerun each version. _v6_0714_arch/ pins the v6 model class.
  presentation/       .pptx generators (they write into runs/<version>/).
runs/<version>/       Everything a run produced:
                        train_*.log        (tracked)
                        checkpoints/*.pth  (gitignored)
                        figures/           (gitignored except *.csv, incl. subdirs)
                        config.json        (tracked, where present)
data/                 Inputs + derived arrays. Gitignored; see data/README.md.
docs/CHANGELOG.md     Checkpoint-incompatible architecture changes, by version.
docs/figures/         Figures committed deliberately (README illustrations).
```

Only `scripts/` and `extra_scripts/` are code. Everything under `runs/` is output,
so it can be regenerated, blanket-ignored, or deleted without touching source.

## Setup

```bash
conda env create -f environment.yml
conda activate downscaling_all
```

No file in this repo hardcodes an absolute path to its own contents —
`scripts/paths.py` resolves those from the repo root, so a clone works wherever it
is checked out. That module also holds the defaults for the two genuinely external
inputs (the upstream `.mat` and the DEM). Override any of these to point elsewhere:

| Variable | Default |
|---|---|
| `WIND_DATA_DIR` | `<repo>/data` |
| `WIND_RUNS_DIR` | `<repo>/runs` |
| `WIND_MAT_PATH` | the upstream `wndata.mat` |
| `WIND_DEM_TIF`  | the Copernicus DEM clip |

`python scripts/paths.py` prints every resolved path and whether it exists —
run it first to check the data tree is where the code expects.

Every script in this repository runs on `environment.yml` alone; nothing here
depends on code that is not bundled.

## Running things

Training:

```bash
cd scripts
python train_new_enscgp_swin.py [--device cuda:N] [--resume PATH] [--max-steps N]
```

The recurring evaluations, pointed at any run's checkpoint:

```bash
cd extra_scripts/swin
python eval_checkpoint.py            --checkpoint ../../runs/<version>/checkpoints/best.pth
python eval_quantile_calibration.py  --checkpoint ...   # PIT histogram + coverage maps
python compare_eigenspectra.py       --checkpoint ...   # spectral fidelity of q50
python eval_pinball_impact.py        --checkpoint ...
python graphing/plot_training_curves.py --log_dir ../../runs/<version>
```

Multi-mode tools take a subcommand: `neighbor_mae.py {rank,mean,sweep-k,baseline}`,
`tune_sigma.py {ssr,mae,decouple}`,
`bias_diagnostic.py --part {a,b,c,d,a_meangate,all}` (`all` runs a–d; `a_meangate`
is opt-in).

## Versioning

A checkpoint-incompatible architecture change gets a git tag (`vN-<date>`), so
`git checkout <tag>` restores the exact model, trainer, and config that produced a
run's checkpoints. **`docs/CHANGELOG.md` is the architecture history** — what broke
compatibility and why, newest first, including the two versions whose source did not
survive. Not every experimental change is tagged; check `git log --oneline` too.

The newest tag is `v7-0729`, and commit `a2d37ad` (`0729_meangate`, not yet
tagged) restores `mean_gate` on top of it — but **neither is the model behind the
results above**, which is `v6-0714`. The v7 line is checkpoint-incompatible with
v6 and is kept for the architecture history; see "Why v6-0714 and not the newer
architecture" under Results. `git checkout v6-0714` restores the model, trainer,
and config that produced the reported numbers.

The `archive/*` tags hold retired lines — `pre-reorg-snapshots` (the original tree),
`resnet-refiner`, `variance-conditioning`. Read one without checking it out:

```bash
git show archive/pre-reorg-snapshots:scripts/0626_v1/new_enscgp_swin.py
```

Their binaries live outside the repo in `../26.6_wind_archive/`.
